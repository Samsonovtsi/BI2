# ТЗ ЭР и АКК: покрытие и следующий этап

Проверка от 23.10.2026 по ТЗ от 25.03.2026 и структуре предоставленных выгрузок.
Документ описывает текущую реализацию и дополнения к ТЗ. Исходное ТЗ не изменено.
Рабочие данные, выгрузки и клиентские строки в репозиторий не включены.
«Реализовано» означает наличие кода и локальную проверку; развёртывание на хостинге
и подключение рабочих источников проверяются отдельно.

## Матрица покрытия

| Требование | Состояние | Что остаётся |
| --- | --- | --- |
| Обзор, аналитика, светофор, калькулятор | Реализованы; отчёты также сохранены | Согласовать состав главной страницы с владельцем продукта |
| Количества, проникновение, доходы, банки | Реализованы в доступных разрезах; методики разделены | Утвердить паспорта метрик и единый критерий доступности сделки для продукта |
| Период, город, ФиФ, грейд | Реализованы | Историческая принадлежность города/сотрудника требует справочников с датами действия |
| РОП, МОП, СП, клиент, сделка | Нет нужных полей в месячных сводных | Стабильные ID и история организационной структуры; роли доступа |
| Лучший/худший город серой областью, выбранный красным | Реализовано для ЭР, АКК, ДомКлик; минимальная база настраивается | Утвердить сопоставимые группы и критерий минимальной базы |
| Тепловая карта и сортировка | Реализовано по продуктам, городам и месяцам | Привязать цвет к утверждённому плану/грейду; сейчас светофор использует заданные общие пороги |
| Средний доход АКК на сделку | Есть средний доход на операцию соответствующего продукта | Для уникальной сделки нужен `deal_id`; одинаковую сделку с несколькими услугами нельзя считать несколько раз |
| Динамика и накопление | Месяц, скользящие 3 месяца, накопление в окне | День/неделя/час, сравнение MTD «день к дню» требуют дат событий |
| Персональные планы | Планы городов, факт, выполнение, разрыв в операциях | Планы сотрудников, согласование, владелец и история изменения плана |
| Оптимальный банк и тарифы | Сохранён сценарный калькулятор по группам чеков, исправлен знак прироста | Тарифы по датам, удержания ЦО, ограничения, расчёт по каждой сделке |
| Сводная Космос | 8 видов сводов, контрольные итоги и сравнение с Картой | Прямое подключение к первичным данным и утверждённый приоритет источников |
| Ежедневное и ручное обновление | Планировщик и кнопка; отдельный источник Космос настраивается переменной | Учётные данные источников, эксплуатационный мониторинг, точное расписание |
| Обновлять изменённые данные | Можно отдельно заменять известный свод | CDC/`updated_at` по строкам, удаления, повторное проигрывание и журнал загрузок |
| История 3 года / конец месяца | Версии завершённых месяцев за 36 месяцев, фактическое время фиксации | Регламент закрытия месяца; несуществующие исторические срезы восстановить из агрегатов нельзя |
| Задержка не более 2 дней | Контроль даты источника и покрытия месяцев | Доказать SLA до уровня события можно только по `event_at` и `source_updated_at` |
| Всплески, падения, нули, конфликты | Диагностика и CSV; текущий месяц не сравнивается с полным | Регистрация инцидента, ответственный, статус, доставка и подтверждение получения |
| Уведомления ответственному | Не настроены | Согласованный канал, адресат, правила частоты и дедупликации |
| Таблицы и графики | Таблицы, линии, столбцы, тепловая карта | Режим для базовой/расширенной аудитории, распределения; круговые только для состава с ≤7 категориями |
| UAT и приёмка | Автотесты расчётов и локальные сценарии браузера | Подписание контрольных наборов владельцем метрик и пользователями |

## Почему нельзя объединить все своды простой суммой

| Источник | Гранулярность / событие | Допустимое использование |
| --- | --- | --- |
| 6 | Уникальный технический номер объекта; финансовая дата; город партнёра; фильтр без ипотеки | Исходный distinct-итог. Для произвольных периодов и групп городов нужны ID |
| 242, города | Операции АКК по городу; исключён ДомКлик | Сверять с банками на общих месяцах после такого же исключения |
| 242, банки | Банк/продукт без города; другой набор лет | Не применять городской фильтр; не сравнивать полные итоги разных периодов |
| 398 | ЭР по городу, отдельная детализация по сервисам | Контроль суммы сервисов по месяцу и городу |
| 335 | Уникальные сделки по дате отправки в Росреестр и городу регистратора | Отдельный этап воронки; не прибавлять к факту ЭР |
| 328 | Заявки по дате создания и городу заявки | Отдельный этап; конверсия требует связи с той же сделкой |
| 534 | Комиссия участника услуги по месяцу закрытия, ограниченный список городов | Доход в рамках фильтра источника; не доход всей сети и не средний на сделку |

Наличие свежей даты выгрузки не подтверждает полноту всех предшествующих месяцев.
`null`-месяц не распределяется между известными месяцами. Дубли названий после
нормализации регистра агрегируются для аддитивных количеств с предупреждением;
смешение латиницы и кириллицы не исправляется автоматически. Без стабильных ID
нельзя установить, являются ли строки дублями одних операций или разными группами.

Сверка с прежней Картой показывает разницу наблюдаемых значений. Причины требуют
проверки состава услуг, даты среза, статуса и привязки города. Ни один источник
не назначается автоматически «истиной» из-за более поздней загрузки.

## Дополнения к паспортам показателей

Для каждой метрики фиксировать: бизнес-владельца, единицу, гранулярность,
числитель, знаменатель, включённые статусы и продукты, событие периода, часовой
пояс, справочники, допустимые фильтры, правила нулей/пропусков, источник и версию
формулы. Изменение формулы не должно незаметно переписывать старые отчёты.

| Показатель | Предлагаемое правило | Обязательная предпосылка |
| --- | --- | --- |
| Проникновение ЭР/АКК | Уникальные подходящие сделки с продуктом / уникальные подходящие сделки | Одинаковая когорта и период; не смешивать операции и объекты |
| Конверсия этапов | Сделки, достигшие следующего этапа / сделки входной когорты | Связанные события по `deal_id`, окно дозревания |
| Средний доход на сделку | Чистый доход / уникальные завершённые сделки с доходом | Единые правила отмен, возвратов, ЦО и даты признания |
| Доход на доступную сделку | Чистый доход / все подходящие сделки | База доступности продукта и единая когорта |
| Выполнение плана | Факт / цель; при нулевой цели отношение не определено | Цель, методика, период и уровень назначения |
| Разрыв до плана | `max(0, ceil(цель × текущая база − факт количества))` | Это оценка при неизменной базе, не прогноз конечного месяца |
| Темп MTD | Факт к той же доле рабочих дней прошлых периодов | Дневные события и календарь; месячная сводная недостаточна |
| Прогноз EOM | Темп с поправкой на сезонность; показывать диапазон | Дневная история, проверка ошибки прогноза на прошлых месяцах |
| Время прохождения этапа | Медиана и P90 разницы дат связанных событий | Стабильные ID, единый часовой пояс, правила незавершённых сделок |
| Потенциал выбора банка | Сумма положительного прироста чистого дохода по допустимым альтернативам | Версионные тарифы, ограничения банков, сумма и срок каждой сделки |
| Полнота данных | Известные обязательные поля / ожидаемые записи | Согласованная ожидаемая популяция, карантин неполных строк |
| Задержка источника | Время загрузки − `source_updated_at`; отдельно возраст события | Это разные часы; дата выгрузки не заменяет оба |

Эти формулы — предложения к согласованию, а не скрытая замена исходных сводов.
Текущие исходные методики и NEW остаются явно разделёнными. Значения >100% не
обрезаются: они служат сигналом проверки знаменателя и повторов.

## Приоритеты автоматизации

### P0 — доверие к данным

1. Справочник `city_id` с алиасами, сроками действия и ручным разрешением конфликтов.
2. Реестр паспортов метрик и договорённость о событии периода для каждого отчёта.
3. Автоматические сверки источник → нормализованные данные → витрина с одинаковыми
   фильтрами. Ошибочные строки помещать в карантин, не заменять нулём.
4. На экране отдельно показывать время загрузки, дату актуальности, последний
   полный период и статус сверки. Контрольные суммы хранить в журнале запуска.
5. Постоянный диск и резервное копирование текущего файлового хранилища.

### P1 — первичные данные и управление

Нужен экспорт/API со следующими полями:

| Сущность | Минимальные поля |
| --- | --- |
| Сделка | `deal_id`, `object_id`, `city_id`, сумма, валюта, признак ипотеки/наличных, тип, статус, финансовая дата |
| Услуга | `service_id`, `deal_id`, продукт, банк, статус, ответственный, отмена/возврат |
| Событие | `event_id`, `service_id`, тип, `event_at`, часовой пояс, `source_updated_at`, признак удаления |
| Оргструктура | ID сотрудника/РОП/МОП/СП, руководитель, город, `valid_from`, `valid_to` |
| Клиент | Стабильный внутренний ID и связь со сделкой; доступ по ролям |
| Доход | ID начисления, услуга, участник, сумма до/после удержаний, ЦО/город, дата признания, возврат |
| Тариф | Банк, продукт, период действия, сумма/срок, минимум/максимум, ставка, удержания, ограничения |

Ввести идемпотентный импорт по ключам и `updated_at`, журнал запусков, обработку
удалений, повторную загрузку корректировок и сверку числа обработанных строк.
Доступ к клиентским данным и изменениям планов ограничить ролями; фиксировать
кто и когда менял план, тариф или справочник. Текущий сервер сохраняет модель
доступа проекта без учётных записей и не обеспечивает эти роли самостоятельно.

### P2 — действия по сигналам

Настроить карточки отклонений с ответственным, статусом, сроком разбора,
ссылкой на подтверждающие данные и причиной закрытия. Сигнал отделять от оценки
сотрудника: сначала проверить полноту источника, размер базы, сезонность и
сопоставимость периодов. После согласования канала добавить уведомления с
дедупликацией и дневной сводкой вместо повторов одного события.

Расширить аналитику драйверами изменения: объём подходящих сделок, проникновение,
средний доход, продуктовый и банковский состав. Подключить когортную воронку,
время между этапами и прогноз только после появления первичных событий.

## Приёмка и эксплуатация

- Синтетические тесты проверяют distinct-итоги, пропуски, недатированные записи,
  разные фильтры банков, планы, сохранение версий и базовые расчёты Карты.
- На предоставленном срезе проверены импорт дополнительной книги без изменения
  Карты, межсводные сверки, контрольный городской отчёт и сохранение архива.
- Браузерная проверка охватывает 12 вкладок, фильтры, серую область сравнения,
  скользящий период, банковские средние, сохранение плана и мобильную ширину.
- До приёмки на рабочем сайте проверить загрузку обеих книг, повторный запуск
  контейнера с тем же томом, доступ к Google, ручной и плановый запуск, журнал
  ошибок, восстановление из резервной копии и контрольные значения владельца.
- Архив фиксирует наблюдавшиеся версии агрегатов завершённых месяцев; он не
  содержит полную копию всех вкладок книги и не заменяет резервную копию источника.
