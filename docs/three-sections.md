# BI2 — единый интерфейс из трёх разделов

Изменения в ветке feature/bi2-three-workspaces-20261027. Базовая арифметика прежней Карты и калькулятора не переписывалась.

## 1. Карта онлайн

Главный раздел. Во внутренней навигации сохранены 11 существующих страниц, в том числе Обзор, Аналитика, Светофор городов, Карточка города, Банки, Номинальные счета, Планы, Отчёты, Космос, Отклонения, Источники.

- Сравнение: серый диапазон лучших и худших городов, красный график выбранного города, линия сети; эталон выбирается в сопоставимой группе с минимальной базой.
- В аналитике есть независимые настройки ФиФ, города и периода для ЭР, АКК и ДомКлик при переключении продукта. Состояние хранится в открытой вкладке.
- Тепловая карта имеет два режима: **факт** (менее 30% — красный, 30–59,9% — жёлтый, от 60% — зелёный; ДомКлик оценивается наоборот) и **выполнение плана по грейду** (менее 80% плана — красный, 80–99,9% — жёлтый, от 100% — зелёный). Планы по A++/A+/A/B/C/D/E вводятся для ЭР и АКК как сценарий в браузере; незаданные цели показываются без оценочного цвета. Эти пороги демонстрационные и пока не утверждены как корпоративный норматив.
- Сортировка тепловой карты, фильтры по грейду вала, ФиФ, месяцу, городу и список планов уже существовали и сохранены.
- Банковский средний доход — на операцию, НЕ на уникальную сделку; для расчёта на сделку требуется deal_id.
- Источники пользователя: «Карта онлайн (ЭР, Аккредитивы)», «Свод ЭР+АКК (копия) (копия)», «Свод по городу NEW». Текущий парсер в основном использует листы «Свод ЭР», «Свод АКК» и реестры. Полную методическую сверку с комбинированным листом нельзя считать проведённой.
- Цепочка город → РОП → МОП → СПН → клиент не может быть честно заполнена данными агрегатов: необходимы ID сделок, сотрудников и история оргструктуры.

## 2. Светофор риелторов

Новый второй верхнеуровневый раздел, независимый от существующего светофора городов.

Работают:
- три независимых переключателя ЭР/АКК/НС (по умолчанию включены все);
- периоды всё время/год/месяц, фильтры город/РОП/МОП, поиск ФИО/партнёр/старший партнёр;
- сортировка, пагинация рейтинга, пять рекордов компании, комиссия и максимум за месяц;
- ветка раскрытия города → РОП → МОП → СПН с количеством связанных клиентов БЕЗ персональных карточек;
- персональный сценарный план по сотруднику и периоду в памяти открытой вкладки.

Проникновение = уникальные подходящие сделки сотрудника с одним или несколькими выбранными продуктами / все подходящие сделки сотрудника × 100%.

Одна сделка с ЭР и АКК учитывается только один раз в числителе. Строки с одинаковым commission_id дедуплицируются при суммировании комиссий.

### Источник для прототипа

Загрузите CSV UTF-8 с разделителем ; или , и столбцами:
deal_id, employee_id, employee_name, deal_date, eligible_cash, product, commission, commission_id, city, partner, senior_partner, rop, mop, spn, tenure_months, client_id.

Продукт — ЭР/АКК/НС либо пусто. Пустой продукт для сделки без допсервиса необходим: если выгрузить только оформленные продукты, знаменатель проникновения будет неправильным. eligible_cash — да/нет либо 1/0. Дата YYYY-MM-DD или DD.MM.YYYY. Максимальный размер CSV в локальном прототипе — 12 МБ, лимит 150 000 строк.

Все строки обрабатываются локально в браузере. Они не отправляются в API сайта и не сохраняются в хранилище сервера. Для постоянной сетевой загрузки нужны авторизация и API корпоративных данных. Для поиска клиента риелтора в сделках допсервисов требуются стабильные CRM ID клиента/сделки, проверка ролей доступа и механизм сопоставления без вывода ПДн посторонним.

В ТЗ «Светофор допсервисов» формула конверсии записана в обратном порядке по сравнению с текстовым пояснением. В прототипе использован числитель по сделкам с продуктами, соответствующий пояснению. Требуется формальное согласование.

## 3. Калькулятор АКК

Внутренние страницы:
- «Правильный выбор» — прежний калькулятор по группам чеков со всеми имеющимися данными;
- «Каталоги ставок» — ссылки на исходные листы «Калькулятор», «Детализация по сделкам», «Матрицы выплат», «Базовые % города» отдельной Google-книги Голендухина.

На странице каталогов работает локальный what-if: КВ по каждому банку, процент удержания ЦО, доход города после удержания и сравнение лучшего ИЗ ВВЕДЁННЫХ вариантов с выбранным фактическим банком. Для Т-Банка можно рассчитать КВ по годовой ставке: сумма × срок дней × ставка / 365.

Результаты каталога не заменяют исходные финансовые данные, не сохраняют изменения ставок в Google Sheets и не обещают правильный выбор из банков, для которых пользователь не ввёл допущенные условия. Для промышленного расчёта по каждой сделке нужны датированные тарифные матрицы, ограничения банков, сумма, срок, фактическая комиссия, удержания и стабильные ID.

## Что осталось до рабочего корпоративного релиза

P0: фактический адрес и конфигурация рабочего сайта; деплой; авторизация BI2; доступ к первичным событиям CRM/BI; паспорта показателей; сверка двух указанных листов Карты с экраном; постоянное хранилище.

P1: серверные персональные планы с аудитом; грейды по плану и продукту; полноценная цепочка до клиента по правам; средняя комиссия АКК на уникальную сделку.

P2: импорт изменяемых версионных каталогов банка и ЦО; оптимальный допустимый банк по каждой сделке; контрольные сравнения с «Детализацией по сделкам» и сквозные тесты.

Новый модуль расчётов покрыт 8 тестами (уникальные сделки, выбранные продукты, дедупликация комиссий, фильтрация, иерархия, валидация CSV). Проверка синтаксиса четырёх новых JS-модулей и эти восемь расчётных тестов прошли в изолированном исполнении. Полный npm test, браузерный E2E и публикация на действующем сервере в этой сессии не выполнялись. Исходные вкладки и API сохранены.
