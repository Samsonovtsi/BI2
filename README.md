# ЭР и АКК — «Этажи.Инсайт»

Node.js/Express, интерфейс без сборки. Разделы: Обзор, Аналитика, Светофор,
Калькулятор, Карточка города, Банки и комиссии, Номинальные счета,
Источники, Отчёты, Космос и сверка, Планы городов, Отклонения и срезы.
Вкладка «Отчёты» сохранена: выбор города, месяца и
методики, печать/PDF средствами браузера, скачивание HTML.

## Запуск и проверка

```bash
npm ci
npm test
npm start
```

Открыть `http://localhost:3000`. Node.js 18+, Docker использует Node.js 20.
Точка входа — `index.js`; `server.js` сохраняет совместимость с прежним запуском.
Для существующего хостинга достаточно пересобрать приложение из репозитория.

Переменные окружения:

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт, по умолчанию 3000 |
| `GOOGLE_SHEET_ID` | ID полной Карты онлайн; по умолчанию прежний источник проекта |
| `GOOGLE_COSMOS_SHEET_ID` | Необязательный ID отдельной книги со сводными Космос |
| `CACHE_FILE` | Путь к агрегированному кэшу; по умолчанию `data/cache.json` |
| `BI2_STATE_DIR` | Планы и архивы; по умолчанию `operations` рядом с `CACHE_FILE` |

Для сохранения загрузок между пересозданиями контейнера нужен постоянный том для
`CACHE_FILE` и `BI2_STATE_DIR`. Файловое хранилище рассчитано на один экземпляр
сервера; несколько реплик требуют общей БД и блокировок. Кэш старой схемы не используется: после обновления потребуется
загрузка полной книги или успешное обновление из Google.

## Загрузка и источники

Кнопка «Загрузить Excel» принимает экспорт Google Sheets в `.xlsx`/`.xlsm`
до 50 МБ. Сервер читает нужные листы по именам, сохраняет только агрегаты.
Сам файл, клиентские ФИО, телефоны, ссылки на сделки и строки реестров в кэш
и браузер не передаются. Лимит обработки — 3 минуты, память worker — до
1536 МБ; хостингу также нужна память для основного процесса. Парсинг вынесен
в worker, чтобы не блокировать ответы API.

«Обновить сейчас» загружает полную книгу через Google XLSX export. Это требует
уже настроенного доступа сервера к источнику. Если Google требует авторизацию,
можно использовать загрузку Excel; открывать клиентскую книгу публично для
работы импорта не требуется. Ошибка обновления сохраняет предыдущий кэш.

| Лист | Что используется на сайте |
| --- | --- |
| Свод ЭР | Даты заголовков, количества, знаменатели, ЭР и ДомКлик; исходные групповые строки |
| Свод АКК | Даты заголовков, количества, знаменатели, проценты и банковские строки |
| ЭР Data | Количество операций по городу и месяцу; сверка со сводом |
| АКК Data | Продукты, количества, F: вознаграждение, I: доход ЦО, J: доход города |
| BI+Космос | Исходное количество сделок с наличными |
| Сумма BI+Космос | Значение средней суммы сделки из источника |
| ДомКлик | Исходное количество операций |
| Каталог городов / Переход на Космос | Город, категория, грейд, исключения, месяц перехода |
| Тех. лист. номинальный счет | Агрегаты город/месяц, суммы, сроки, доходы, статусы |
| Ставка Т банк | Период доступных ставок; старые ставки автоматически не применяются |
| Свод по городу NEW | Сохранённые контрольные значения выбранного в книге города |
| Калькулятор | Существующий отдельный шаблон по чекам; поддерживается отдельный Excel |

Список остальных листов показан в «Источниках». Прозвоны, заявки, редактирование
реестров, истории действий и права сотрудников пока не перенесены.

Калькулятор продолжает использовать отдельную исходную таблицу. Его город и
период не зависят от фильтра карточки. Без листа «Калькулятор» импорт сохраняет
предыдущий расчёт с отдельной отметкой источника. Изменение срока не моделируется;
соответствующее поле отключено. Это готовый расчёт исходного шаблона.
Потенциальный прирост считается как сумма `max(0, лучший доход − фактический)`
по группам чеков. Сценарий масштабирует сохранённый расчёт; актуальные тарифы,
удержания ЦО, ограничения банков и выбор по отдельной сделке ещё не моделируются.

## Сводные Космос и контроль показателей

Отдельная книга Космос дополняет Карту онлайн, сохраняя её своды, реестровые
агрегаты и калькулятор. Поддержаны отчёты 6, 242 (города и банки), 398 (города и
сервисы), 335, 328, 534. Можно загрузить один известный лист: заменяется весь
соответствующий свод, остальные источники сохраняются. Срез с более ранней
датой актуальности отклоняется; время внутри одного дня пока не сравнивается.
Это обновление отдельных сводов, а не инкрементальная загрузка строк по ID.

- Для distinct-показателей используются исходные итоги. Произвольная сумма
  городов не рассчитывается без идентификаторов объектов/сделок.
- АКК городов сверяется с банковской детализацией на общих месяцах после
  исключения ДомКлик, если такой фильтр явно указан в источнике.
- ЭР 398 сверяется с детализацией по сервисам по месяцам и городам.
  Отправки 335 и заявки 328 — отдельные события, их нельзя прибавлять к 398.
- `null` в месяце и городе сохранён как неизвестная принадлежность.
  Внутри экспортированной сводной пустая группа считается нулём; отсутствующий
  месяц или ошибочное значение остаётся неизвестным. Столбцы темпов роста
  исключены из суммирования. Это правило отличается от пустой формулы в Карте.
- Отчёт 534 сохраняет фильтры городов и сумму комиссии участников услуг;
  его итог не выдаётся за весь доход сети или доход на уникальную сделку.
- Сверка с Картой онлайн и сигналы отклонений доступны в CSV. Расхождения
  показываются отдельно и не переписывают исходные показатели.

Аналитика поддерживает ЭР, АКК и ДомКлик, месячную динамику, скользящие три месяца
и накопление в выбранном окне. Многомесячный процент — отношение сумм числителей
и знаменателей. Пропущенные месяцы не заполняются нулём. Серый диапазон лучших
и худших городов учитывает ФиФ/грейд и минимальную месячную базу; выбор города
оставляет группу сравнения. Для ДомКлик меньшая доля конкурента считается лучше.

Планы сохраняются по ключу «город / продукт / месяц / методика». Факт и число
недостающих операций рассчитываются по той же методике при текущей базе.
Нулевой план сохраняется, выполнение в процентах при нулевой цели не вычисляется.
Средние банковские доходы делятся на число операций соответствующего продукта,
а не на неподтверждённое число уникальных сделок.

После успешного разбора данных сохраняются неизменяемые версии завершённых
месяцев за последние 36 месяцев. Архив включает записи аналитики Карты и
месячные агрегаты Космос с метаданными; калькулятор, каталог и отдельный реестр
номинальных счетов в него пока не входят. Содержимое дедуплицируется по хешу.
Дата фактической фиксации указана явно: это наблюдавшиеся версии, не гарантированные
исторические срезы на конец месяца. Текущий месяц определяется по Екатеринбургу.

Правила отклонений: процент выше 100, скачок от 20 п.п. при базе от 20 в обоих
месяцах, три последовательных нуля при положительной базе, падение количества
ЭР/АКК Космос от 20% и 5 операций при прошлом объёме от 20, дата актуальности
источника старше двух дней и недостающие завершённые месяцы. Текущий месяц
исключён из скачков/серий нулей. Пороговые правила требуют согласования; доставка
уведомлений не настроена. Полная матрица ТЗ и следующие этапы —
[docs/requirements-audit.md](docs/requirements-audit.md).

## Методики и пропуски

- **Исходные своды:** сохраняются числитель, знаменатель и процент источника.
  Для одного города и месяца показывается сохранённый процент; для нескольких
  городов/месяцев — сумма операций / сумма знаменателей, а не среднее процентов.
- **Свод по городу NEW:** количества из реестров, база `BI+Космос × коэффициент`:
  Москва 0,5; Тюмень 1; остальные 0,65. Групповая база — сумма баз городов.
  Это явно обозначенная методика, а не автоматическое исправление исходной книги.
- Карточка, банковские суммы и отчёт используют один модуль агрегации.
  Выбор методики в карточке не изменяет исходные графики сводов.
- Пустые ячейки, ошибки формул и отсутствующие месяцы остаются неизвестными (`—`).
  Ноль остаётся нулём. При неизвестном компоненте общий итог также неизвестен.
  Отсутствие операций в реестре трактуется как ноль только внутри месяцев,
  представленных в этом реестре; импорт предполагает полную выгрузку реестра.
- Даты АКК читаются из заголовков. Совпадение соседних значений не является
  основанием удалять месяцы. Повторяющиеся заголовки отклоняются.
- Категории Ф4/Ф5 и исключённые города не входят в общий итог карточки.
  Явный выбор города позволяет посмотреть его данные отдельно.
- Средний чек за период взвешивается по количеству сделок с наличными при наличии
  всех исходных компонентов. Нули/пропуски исходного среднего требуют проверки.
- Номинальные счета относятся к месяцу раскрытия; если даты нет — к месяцу
  пополнения с отдельной отметкой. Это разные основания периода, не единая
  оценка остатка на счёте. Доход берётся из книги, а не пересчитывается по ставке.

«Источники» разделяют время загрузки и период фактических данных, показывают
ошибки сохранённых формул, расхождения количеств, баз и неизвестные продукты.
Импорт не пересчитывает Excel-формулы: используются сохранённые значения экспорта.

## API и структура

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/data` | Текущий агрегированный кэш; устаревший кэш обновляется в фоне |
| POST | `/api/refresh` | Обновление из Google Sheets |
| POST | `/api/upload` | Multipart-поле `file`, сводка импорта |
| GET | `/api/health` | Состояние процесса и версия схемы |
| GET / PUT | `/api/plans` | Список / сохранение плана города |
| DELETE | `/api/plans/:id` | Удаление плана |
| GET | `/api/snapshots` | Список версий завершённых месяцев |
| GET | `/api/snapshots/:id` | Агрегаты конкретной версии, JSON |

Кэш сохраняется атомарно, TTL — 24 часа. Планировщик проверяет источники раз в
час при работающем сервере; после неудачной попытки действует часовой интервал
повтора. Свежая загрузка Космос не откладывает обновление Карты. Это не гарантия
обновления в определённое время суток: нужен постоянно работающий процесс и
доступ к Google. Одновременно обрабатывается одна книга.
При первом запуске без доступных источников старый снимок ЭР и калькулятора
помечен резервным. Недостоверный старый снимок АКК удалён; новые разделы ждут
полную книгу. Приложение сохраняет прежнюю модель доступа без встроенных учётных
записей; доступ к агрегатам и загрузке должен ограничиваться средствами хостинга,
если сайт используется как внутренний сервис.

- `lib/workbook-data.js` — нормализация и агрегация исходных листов.
- `lib/workbook-loader.js`, `lib/import*.js` — XLSX и worker.
- `lib/calculator.js` — отдельный существующий шаблон калькулятора.
- `lib/sheets.js` — Google export, обновления и кэш.
- `lib/cosmos.js` — разбор и сверка сводных Космос.
- `lib/operations.js` — планы и архивы завершённых месяцев.
- `public/insight-model.js`, `public/insights.js` — сводные, планы и диагностика.
- `public/analytics.js` — общие расчёты карточки/отчёта и новые разделы.
- `public/index.html`, `public/analytics.css` — интерфейс и стили.
- `test/workbook.test.js` — даты, методы, пропуски, банковские продукты,
  исключения, отсутствие клиентских данных в агрегатах и импорт worker.
- `test/cosmos.test.js` — сводные, фильтры, distinct, пропуски, планы и архивы.

Тестовые данные синтетические. Рабочая книга и кэш не включаются в Git.
