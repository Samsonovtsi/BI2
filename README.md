# ЭР и АКК — дашборд «Этажи.Инсайт»

Дашборд с бэкендом на Node.js/Express. Бэкенд сам ходит в Google Sheets,
разбирает данные и отдаёт их фронтенду через свой API. Вкладки: Обзор ·
Аналитика · Светофор · Калькулятор — по ТЗ отдела ЭР и АКК.

```
dashboard-repo/
├── index.js           ← Express-сервер: раздаёт фронтенд + API (точка входа)
├── server.js           ← совместимая обёртка (import './index.js') — на случай,
│                          если где-то в настройках хостинга закреплено имя server.js
├── lib/sheets.js      ← загрузка Google Sheets (CSV), парсинг, кэш
├── public/index.html  ← фронтенд (чистый HTML/CSS/JS, без сборки)
├── data/               ← сюда сервер пишет кэш (data/cache.json), в git не идёт
├── package.json
├── Dockerfile
└── README.md
```

## Как это работает

**Бэкенд** (`index.js` + `lib/sheets.js`):
- при первом запуске и раз в час проверяет, не устарел ли кэш (> 24 часов) —
  если да, сам подтягивает свежие данные из двух Google-таблиц через их
  CSV-экспорт (`.../export?format=csv&gid=...`), парсит по тем же
  координатам столбцов, что и раньше (карта проникновения ЭР по городам,
  разбивка калькулятора АКК по чекам), и кладёт результат в кэш —
  **в памяти процесса** и **на диск** (`data/cache.json`, переживает
  перезапуск процесса);
- `GET /api/data` — отдаёт то, что в кэше, мгновенно; если кэш старше
  24 часов, дополнительно запускает фоновое обновление (ответ при этом
  не ждёт его — отдаёт текущие данные сразу);
- `POST /api/refresh` — форсирует свежую загрузку из Google Sheets и
  ждёт её результата, прежде чем ответить (это дергает кнопка «Обновить
  сейчас» на фронтенде);
- `GET /api/health` — для healthcheck (можно указать в настройках
  App Platform);
- если Google Sheets недоступны при самом первом запуске (и на диске нет
  кэша) — отдаёт встроенный резервный снимок (`DEFAULT_DATA` в
  `lib/sheets.js`), чтобы дашборд не был пустым.

**Фронтенд** (`public/index.html`) не ходит в Google напрямую — только
в свой же бэкенд (`fetch('/api/data')`, `fetch('/api/refresh', {method:'POST'})`).
Если бэкенд совсем недоступен, фронтенд показывает встроенный клиентский
резервный снимок и предупреждение.

**Важно про доступ к таблицам:** обе Google-таблицы должны быть открыты
по ссылке — «Доступ по ссылке → Читатель». Если доступ закроют, бэкенд
не упадёт — вернёт последний сохранённый кэш и залогирует предупреждение.

**Загрузка Excel-файла (`POST /api/upload`):** кнопка «Загрузить Excel» в
шапке дашборда позволяет закинуть выгрузку таблицы «Карта онлайн (ЭР,
Аккредитивы)» (Файл → Скачать → Microsoft Excel в Google Sheets) прямо в
сервис, без необходимости искать `gid` нужных вкладок. Бэкенд ищет в файле
листы «Свод ЭР» (полная история ЭР/Дом Клик), «Свод АКК» (аккредитивы по
банкам и городам) и «Калькулятор» (разбивка по чекам), разбирает их той же
логикой, что и для живых Google Sheets, обновляет текущий кэш дашборда и
возвращает сводку — какие листы найдены и за какие месяцы/по каким
городам реально пришли данные. Полезно, если правильные `gid` вкладок
найти через браузер не получается, или если нужно подгрузить данные,
которых ещё нет в живом источнике.

## Запуск локально

```bash
cd dashboard-repo
npm install
npm start
# откройте http://localhost:3000
```

Порт можно поменять переменной окружения `PORT`.

## 2. Деплой в Timeweb Cloud (App Platform)

Теперь это полноценное backend-приложение — нужен вариант, который умеет
запускать процесс, а не просто раздавать статику.

### Вариант A — тип «Dockerfile» (рекомендуется, полный контроль)

В репозитории уже есть готовый `Dockerfile`.

1. Timeweb Cloud → **App Platform** → **Создать приложение**.
2. Тип — **Dockerfile**.
3. Подключите GitHub-репозиторий, ветка `main`, путь к директории проекта
   оставить пустым (Dockerfile в корне).
4. Порт уже прописан (`EXPOSE 3000`) — трогать не нужно (это порт по умолчанию, который сканирует Timeweb App Platform; если платформа передаёт свою переменную `PORT`, приложение использует её).
5. При желании укажите healthcheck-путь `/api/health`.
6. Запустить деплой. Автодеплой на новый коммит включён по умолчанию.

### Вариант B — нативный тип «Express» (Node.js)

Timeweb App Platform умеет собирать Express-приложения напрямую, без
Dockerfile (ставит зависимости через `npm install` и запускает через PM2).

1. **App Platform** → **Создать приложение** → раздел **Backend** → **Express**.
2. Подключите тот же репозиторий, ветка `main`.
3. Рантайм — **Node.js** (18/20/22).
4. Точка входа — `index.js` (команда запуска берётся из `package.json` →
   `scripts.start`, он уже настроен на `node index.js`). Важно: нативный тип «Express» в Timeweb сам через PM2 ищет именно `index.js` в корне — другое имя файла приводит к ошибке «Script not found».
5. Запустить деплой.

В обоих случаях после деплоя Timeweb выдаёт бесплатный технический домен
(`*.twc1.net`), свой домен привязывается там же в панели приложения.

## 3. Если понадобится изменить логику разбора таблиц

Вся логика — в `lib/sheets.js`:

- `SHEET_MAP` / `SHEET_CALC` — id и `gid` листов;
- `colIndex('BW')` — конвертер буквенных адресов столбцов Google Sheets
  в индексы массива;
- `buildMapData()` — сборка данных по городам (карта проникновения ЭР);
- `buildCalcData()` — сборка данных калькулятора АКК по чекам;
- `CACHE_TTL_MS` — интервал автообновления (сейчас 24 часа).

Если в исходных таблицах добавят строки/столбцы или переименуют листы —
проверьте константы `MAP_TRIPLES`, `MAP_NASHA_BAZA_SLOTS` и номера строк
в `buildCalcData()` (`row 3` — target%, `row 4/5` — период, `row 7` —
город, `row 11..` — строки чеков) и поправьте под новую раскладку.

`DEFAULT_DATA` в начале `lib/sheets.js` — резервный снимок на случай
полной недоступности таблиц; его можно периодически освежать вручную тем
же способом, каким наполнялась первая версия дашборда.
